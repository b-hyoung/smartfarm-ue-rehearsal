3문헌의 구성

최소 전력과 균일도를 같이 다룬 연구는 대부분 같은 네 단계를 쓴다.

  1. CFD 케이스 — 실험계획법으로 조건을 배치한다.
  2. 대리모델 — 응답곡면(RSM), 신경망, POD-신경망. 케이스가 적으면 RSM·가우시안 프로세스가 많다.
  3. 다목적 최적화 — NSGA-II로 파레토 해를 얻는다. 계산이 비싼 경우 베이지안 최적화.
  4. 최종안 선택과 확인 — TOPSIS 등으로 하나를 고르고 CFD로 다시 확인한다.

4우리 구성 (예정)

  1. 학습 데이터 정리 (완료, GPT 교차검증) — cases.csv의 팬 위치 열을 CFD가 실제로 쓴 fan_zones 기준으로 고쳤다. 꺼진 팬이 빠지고 흡입기는 바깥을 향한다. 학습표에는 오류(E-004~006) 표시 열을 붙였고, 풍량은 추력 환산용 명목값이다.
  2. 목표 단일 출처 — 위 기준값을 설정 파일 하나에 두고 채점기와 최적화가 같이 읽는다.
  3. 팬 데이터시트 (완료, 추정식) — W1G200-CI77-52 기준 P = P₀ + k·Q³. “팬 데이터시트” 탭.
  4. 대리모델 — 현재 운전 상황(에어컨 기준 위치, 마주보기, 15°, +0.18 m)에 맞는 13 케이스만 쓴다: 02 R1 · 03~08 F1~F6 · 09~14 S1~S6. 입력은 팬 네 대 각각의 풍량(꺼짐 = 0), 출력은 두 단의 적정 면적과 P10. 학습표 data/fan-dataset/current_subset.csv.
  5. 최적화 — 풍속 제약을 지키는 최소 전력 후보를 찾는다. 대리모델 불확실성이 큰 후보는 “미검증”으로 따로 표시한다.
한계. 모든 값은 실측이 아니라 CFD 계산값이며 E-004(에어컨 수직 취출) · E-005(취출 속도 절반) · E-006(선반 열 278 W)이 들어 있다. 여기서 찾는 최적은 이 CFD 설정의 최적이다. 실측으로 확정된 것은 방 크기뿐이다.

1무엇이 틀렸나

CFD 생성기는 fan_params.json의 fan_zones(켜진 팬마다 위치·방향·추력)로 계산했다. 그런데 데이터셋 스크립트 make_fan_dataset.py는 이 값을 읽지 않고 배치 규칙으로 팬 위치를 다시 계산했다. 그 규칙은 꺼진 팬도, 흡입기도 몰랐다.

3GPT(Codex) 교차검증

수정 커밋을 GPT(Codex)에 넘겨 원본 코드와 데이터를 따로 대조하게 했다. 파일은 고치지 않는 읽기 전용 검토였다.

검증 항목판정근거
CFD가 실제로 fan_zones를 썼나맞음생성기가 꺼진 팬을 빼고 fan_zones로 격자 영역과 운동량 소스를 만든다. 저장된 18 케이스 실행 로그의 켜진 팬도 일치
새 팬 위치 열맞음30행 모두 대수 = 켜진 팬 수, 좌표·방향이 원본과 일치. 바뀐 것은 이 열 25개 값뿐
흡입기 방향 (1,0,0)맞음양의 추력 × 방향 벡터로 넣으므로 재배단 바깥으로 공기를 미는 흡입팬 표현이 맞다. 예전 표가 부호 관례상 맞았을 가능성은 없음
13 케이스 학습표맞음필터 결과가 정확히 02, 03~14. 팬 네 대 풍량과 출력 130개 값이 원본 점수와 일치. 모두 저장본 6장
옛 규칙 대체 경로틀림 → 고침팬 정보가 비면 CFD에 없는 팬을 지어냈다
학습표의 해석확인 필요 → 표시 추가풍량은 추력 환산용 명목값이고, 13행 모두 E-004~006 오류를 안고 있다

남은 확인 사항: 실행 당시 케이스별 fvOptions 파일은 저장소에 없어서, 실행 중 수동 변경이 없었다는 것까지는 확증하지 못했다.

4바뀌지 않은 것

  • CFD 결과와 점수표(scores.csv, judge.json)는 그대로다.
  • 목표 탭의 판정표는 점수표에서 나오므로 이번 수정으로 값이 바뀌지 않는다.
  • E-004 · E-005 · E-006 오류는 그대로 남아 있다. 이번 수정은 학습 입력 표기만 바로잡았다.
