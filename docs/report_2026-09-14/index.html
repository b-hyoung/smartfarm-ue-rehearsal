열·유동 CFD와 언리얼 통합 리허설

임시값(목데이터)으로 구동하는 트윈 구조와 실측·장비 도착 시 교체 지점

요약

본 문서는 스마트팜 공간의 온도·기류·전력을 언리얼 엔진에서 조작하고 확인하는 디지털 트윈 과제 가운데, 열·유동 해석 결과를 언리얼로 인계하고 조건 변경에 따른 예측 갱신 구조를 선구축한 범위를 정리한다. 실측 장비와 조명 배광 파일(IES)이 확보되기 전이므로, 모든 입력은 실데이터와 동일한 형식의 임시값으로 채워져 있다. 따라서 장비가 도착하면 코드와 화면을 바꾸지 않고 입력 파일만 교체하여 작업을 이어갈 수 있다.

문서는 전체 흐름에서의 수행 범위, 목데이터의 종류·형식·생성 방식·교체 조건, 실제 CFD 결과와 언리얼 시각화, 에어컨·재배단 위치 변경에 따른 예측 갱신, 검사·역산 리허설, 냉방·조명 전력량 계산, 장비 도착 이후의 작업 순서를 차례로 기술한다.

1과제 개요와 수행 범위

스마트팜에서 냉방기 위치나 설정, 조명 출력을 바꾸었을 때 공간의 온도·기류·전력이 어떻게 달라지는지를 매번 실측하거나 매번 CFD를 수 시간씩 계산하여 확인하기는 어렵다. 본 과제는 소량의 실측으로 시뮬레이터를 교정하고, 교정된 시뮬레이터가 만든 대량의 결과를 AI 대리모델이 학습하게 하여, 언리얼에서 조건을 바꾸면 초 단위로 예측을 보여주는 구조를 목표로 한다.

1.1전체 흐름과 본 작업의 위치

과제는 여섯 역할(R1~R6)로 나뉘고, 데이터는 실측에서 시작해 언리얼 화면에서 끝난다. 아래 도식에서 굵은 청록 테두리 영역이 본 작업이 수행한 범위다. 본 작업은 R3 열·유동 해석 결과를 R6 언리얼로 인계하는 구간을 실데이터로 완성하였고, 아직 입력이 없는 R1·R2·R4·R5의 자리는 같은 형식의 임시값과 리허설로 채워 흐름 전체가 끊기지 않고 동작하게 하였다.

1.3오프라인 계산과 실시간 응답의 경계

수 시간이 걸리는 CFD 계산, 케이스 대량 생산, 대리모델 학습, 미지 물성값 역산은 사용자가 화면을 열기 전에 끝나 있어야 하는 오프라인 작업이다. 언리얼에서 조건을 바꾸는 순간에는 학습된 예측기에 조건을 넣어 결과를 그리는 일만 수행한다. 현재 이 실시간 자리에는 수 초 안에 답하는 임시 수식 예측기가 들어가 있으며, 학습 범위 밖의 조건은 오프라인 재계산 대상으로 넘긴다.

3목데이터(임시값) 명세

현재 트윈은 실측과 장비 사양이 없는 상태에서 동작하므로, 입력의 상당 부분이 임시값이다. 이 장은 무엇이 임시값인지, 어떤 방식으로 만들어져 어떤 파일로 들어가는지, 무엇이 오면 어느 파일이 교체되는지를 정리한다.

3.1설계 원칙

  1. 형식은 실데이터와 동일하다. 임시값 파일의 열 이름·단위·좌표·시각표는 실제 CFD 반출물과 같다. 소비하는 쪽(언리얼·웹·학습기)은 공급원을 구분하지 않는다.
  2. 출처를 파일 안에 새긴다. source 항목에 MOCK을 넣고 화면에 표시하여, 임시값이 결과로 오인되지 않게 한다.
  3. 교체 단위는 한 곳이다. 임시값을 만드는 부분이 한곳에 모여 있어, 실데이터가 오면 그 부분 또는 입력 데이터만 바뀐다.
  4. 실데이터 보호. 임시 예측기가 실데이터 파생물을 덮기 전에 한 번 백업 폴더로 대피시킨다.

H. 예상 소비전력 (JSON)

웹 대시보드의 소비전력 타일과 언리얼 재생 중 3D 텍스트가 읽는 파일이다. 모든 값이 임시값 COP·조명 와트에 의존한다.

  1. 측정점 시계열에서 A 지점 1.7 m 온도를 리턴 공기온도로 읽는다.
  2. 열제거율 Q = (25 CMM ÷ 60) × 1.17 kg/m³ × 1006 J/kg·K × (Treturn − 16.35 ℃)로 계산하고, 음수는 0으로 둔다.
  3. 냉방 소비전력 P = Q ÷ COP 3.5 + 팬 90 W를 구해, 프레임 시각 15개에 가장 가까운 값을 뽑는다.
  4. 조명 전력 = pct/100 × 480 W, 15분 적산 = ∫P dt(사다리꼴) + 조명 전력 × 0.25 h.
{
  "format": "JSON",
  "schema": {
    "t": {

언리얼 레벨은 D자 바닥, 방 윤곽, 에어컨 카세트(판넬·취출 슬롯 4·리턴), A~D 위치 마커로 구성된다. 기류는 4방향 취출 커튼으로 표현하며, 커튼의 색은 그 지점의 온도다. 아래는 vane25 실데이터를 프레임별로 레벨에 올려 SceneCapture로 촬영한 결과다. 냉방이 진행되며 커튼 끝자락이 청록에서 남색으로 바뀌어, 방 전체가 식어 제트가 덜 데워지는 과정이 드러난다.

그림 4-2. 언리얼 캡처, vane25 커튼 15프레임 중 5장. 윗줄은 평벽 쪽에서 방 안쪽을 본 시점, 아랫줄은 위에서 본 시점이다. 아랫줄은 평면도와 방향을 맞추기 위해 상하 반전하였다(언리얼은 왼손 좌표계). 색 척도 20.4~28.9 ℃ 고정. 재배단은 CFD 격자에 포함되지 않았으므로 해석 화면에서는 숨긴다.

재생 방식

15프레임은 시퀀서에 올라가 재생 1초 = 실제 30초(30배속, 32초 루프) 또는 10초(10배속, 90초)로 재생되며, 프레임 사이는 색 번짐과 커튼 모핑으로 보간된다. 툴바의 [SF 30배속]·[SF 10배속]·[SF 정지] 버튼으로 전환한다. 재생 중 프레임별 예상 소비전력이 3D 텍스트로 표시된다.

4.4웹 미리보기

언리얼 3D 화면은 단면·커튼·화살표가 한 원근에 겹쳐 서로를 가리므로, 같은 데이터를 2D로 분리해 보는 웹 대시보드와 공간·조명 배치를 확인하는 3D 배광 미리보기를 함께 제공한다. 두 페이지는 데이터가 내장된 단일 HTML 파일이다.

5라이브 트윈 — 위치 변경에 따른 예측 갱신

라이브 트윈은 언리얼에서 에어컨이나 재배단을 끌어 옮기고 버튼을 누르면, 새 배치에서의 예상 온도·기류·전력으로 화면이 다시 재생되는 기능이다. 위치 변경은 두 경로로 처리된다. 즉시 응답 경로는 예측기로 수 초 안에 화면을 갱신하고, CFD 경로는 같은 위치로 새 경계조건을 만들어 정식 해석을 다시 수행한다.

5.1언리얼에서의 위치 변경 결과

7냉방·조명 전력량 계산

냉방기 전력 실측이 없는 상태에서, CFD 또는 예측기가 내놓는 리턴 공기온도로 냉방기의 열제거율을 구하고 가정 COP로 나누어 소비전력과 15분 전력량을 산출한다. 조명 전력은 점등률에 가정 와트를 곱해 더한다. 결과는 전력 결과로 저장되어 웹 대시보드와 언리얼 재생 화면에 표시된다.

7.1계산식

  1. 측정점 시계열에서 point = A, z = 1.7인 행만 골라 시각 순으로 정렬한다. vane25는 1,017행, 수직취출은 768행이다.
